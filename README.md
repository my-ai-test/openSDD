# SDD Framework V4

**Spec-Driven Development** — 让 AI 编码从规格出发，而非从猜测出发。

这是一个 **git submodule 式框架**，安装后为 Claude Code 注入：
- 7 个 **Skills**（`/sdd-*` 斜杠命令）引导完整开发流程
- 3 个 **Hooks** 强制执行「先写规格，再写代码」原则
- `CLAUDE.md` 模板 + 13 个规格文件模板，开箱即用

---

## 快速上手（5 分钟）

### 1. 添加 submodule

```bash
git submodule add https://your-git-server/sdd-framework.git sdd-framework
git submodule update --init
```

### 2. 运行安装器

**Linux / macOS / Windows Git Bash：**
```bash
bash sdd-framework/install.sh
```

**Windows PowerShell：**
```powershell
.\sdd-framework\install.ps1
```

安装器自动完成：
- `skills/<name>/SKILL.md` → `.claude/skills/<name>/SKILL.md`（symlink 或 copy）
- `hooks/*.sh` → `.claude/hooks/`（copy，带执行权限）
- 生成 `.claude/settings.json`（含绝对路径，机器级配置）
- 生成 `CLAUDE.md`（如不存在，从模板生成）

### 3. 填写 CLAUDE.md

打开根目录的 `CLAUDE.md`，替换所有 `{{PLACEHOLDER}}`：

| 占位符 | 示例 |
|--------|------|
| `{{PROJECT_NAME}}` | `MyApp` |
| `{{TECH_STACK}}` | `NestJS 10 + Next.js 14 + MySQL 8` |
| `{{CODE_DIRS}}` | `` `apps/`、`packages/` `` |
| `{{SPEC_DIR}}` | `SDD/01-specs` |
| `{{BACKLOG_PATH}}` | `SDD/BACKLOG.md` |
| `{{FRAMEWORK_DIR}}` | 已由安装器自动填充 |
| `{{ENTERPRISE_RULES}}` | 删除此行或取消注释企业规范节 |

### 4. 更新 .gitignore

```gitignore
# SDD Framework — machine-local, generated by install.sh
.claude/settings.json
.claude/.session-spec-touched
```

> **注意**：`.claude/skills/` 和 `.claude/hooks/` 也是本地生成的，不需要提交。如果你的 `.gitignore` 已经包含 `.claude/`，则无需额外配置。

### 5. 重启 Claude Code 会话

Hooks 在会话启动时激活。关闭并重新打开 Claude Code，然后开始使用：

```
/sdd-init-project    # 从零启动新项目
/sdd-implement-feature   # 实现一个功能特性
```

## 包含内容

### Skills（`/sdd-*`）

| Skill | 层级 | 说明 |
|-------|------|------|
| `/sdd-init-project` | L3 | 从零启动项目：战略设计 → BC 清单 → 规格骨架 → 实现 |
| `/sdd-implement-feature` | L2 | 实现一个 FD：分析 → AC → API契约 → 代码 → 测试 → 自检 |
| `/sdd-bc-design` | L2 | 设计限界上下文：战略建模 → 聚合/值对象 → BC spec |
| `/sdd-write-ac` | L1 | 生成验收标准：六层展开 → EARS 格式 → 端点覆盖矩阵 |
| `/sdd-write-tests` | L1 | 从 AC 推导测试：工厂函数 → 六层模型 → Mock 规范 |
| `/sdd-generate-uj` | 工具 | 生成用户旅程（A/B/C/D 四类）+ 用户故事 |
| `/sdd-review-spec` | 工具 | 规格质量审查：AC 格式 + 覆盖矩阵 + 企业规范合规 |

调用链：

```
/sdd-init-project
  └─ /sdd-bc-design (×N BC)
  └─ /sdd-implement-feature (×M FD)
       ├─ [可选] /sdd-generate-uj
       ├─ /sdd-write-ac
       └─ /sdd-write-tests
```

### Hooks（Spec-First 守护层）

| Hook | 触发时机 | 作用 |
|------|---------|------|
| `session-reset.sh` | 每次新会话 | 清除上次 session 的 spec-touched 标记 |
| `spec-first-guard.sh` | Edit/Write 代码文件前 | 检查本 session 是否已修改过 spec，否则阻断 |
| `spec-touched-marker.sh` | Edit/Write spec 文件后 | 写入标记，解锁后续代码编辑 |
| `parse-hook-input.js` | 被 `.sh` 脚本调用 | 解析 Claude Code hook 传入的 JSON 输入参数（辅助脚本）|

**紧急绕过**（留审计痕迹）：
```bash
echo "bypass: <原因>" > .claude/.session-spec-touched
```

| `L1-API_SPEC.md` | API 规格（§9 端点契约）|
| `L1-DATA_SPEC.md` | 数据模型规格 |
| `L1-SECURITY_SPEC.md` | 安全规格 |
| `L1-UI_SPEC.md` | UI/交互规格 |
| `L1-USER_JOURNEY_SPEC.md` | 用户旅程规格 |
| `L1-DDD_SPEC.md` | DDD 架构规格 |
| `L1-DOMAIN_EVENT_CATALOG.md` | 领域事件目录 |
| `L1-TEST_DESIGN_SPEC.md` | 测试设计规格 |
| `L2-ARCHITECTURE_PLAN.md` | 架构方案 |
| `L3-BACKLOG.md` | 技术欠账清单 |

### CLAUDE.md 模板（`templates/`）

| 模板 | 适用场景 |
|------|---------|
| `CLAUDE.md.template` | 完整版（11 条规则，含企业规范）|
| `CLAUDE.md.lite.template` | **渐进采用版**（3 条核心规则 + 升级路径，推荐新团队从这里开始）|

### 框架标准（`standards/`）

> 这里是框架核心概念的**单一权威来源**，Skills 和 CLAUDE.md 模板中的内联说明均以此为准。
> 维护框架时只需更新这两个文件。

| 文件 | 内容 |
|------|------|
| `six-layer-model.md` | 六层展开模型完整定义：覆盖要求矩阵、AC 类型识别指南、展开示例 |
| `error-code-format.md` | 错误码格式标准：4 段格式定义、常用异常名约定、HTTP 状态码规范 |

### 完整示例（`examples/minimal/`）

一个最小可运行的 SDD 示例（FD-01 用户注册），展示完成态的规格和测试长什么样：

| 文件 | 说明 |
|------|------|
| `README.md` | 示例导读 + SDD 执行过程回放 + 自检表 |
| `spec/fd-01-register.spec.md` | 完整 Feature Spec（AC、BR、端点覆盖矩阵）|
| `tests/user.aggregate.spec.ts` | Domain 层测试（六层推导，TypeScript）|
| `tests/user-registration.app-service.spec.ts` | AppService 层测试 |

### 质量工具（`scripts/`）

| 脚本 | 用途 |
|------|------|
| `check-sdd-coverage.sh` | 扫描 git 提交历史，计算"代码变更同时含 spec 变更"的覆盖率；支持 `--fail-below` 阈值用于 CI/CD |

## 团队推广

### 已有项目迁移

1. 添加 submodule，运行安装器
2. 填写 `CLAUDE.md`（重点：`{{ENTERPRISE_RULES}}` 节配置企业规范）
3. 将现有 spec 文件整理到 `SDD/01-specs/`（路径可自定义）
4. 第一次使用 `/sdd-review-spec` 检查现有规格的覆盖率

### 新项目启动

```
/sdd-init-project
```

### 环境变量覆盖（`install.sh` 参数）

不同项目的代码目录和规格目录不同，可在安装时覆盖默认值：

```bash
# 自定义代码目录 regex
SDD_CODE_DIRS_REGEX='/(src|lib|server)/' bash sdd-framework/install.sh

# 自定义 spec 目录 regex
SDD_SPEC_DIR_REGEX='/specs/' bash sdd-framework/install.sh
```

或直接编辑安装后的 `.claude/settings.json`。

### 更新框架版本

```bash
git submodule update --remote sdd-framework  # 拉取最新版本
bash sdd-framework/install.sh                 # 重新安装
# 重启 Claude Code 会话
```

## 原理说明

```
┌─────────────────────────────────────────────────────┐
│  用户消息                                            │
│     ↓                                               │
│  Skills (引导层)  ←  /sdd-implement-feature          │
│     告诉 Claude "怎么做好"（方法论）                  │
│     ↓                                               │
│  CLAUDE.md (规则层)                                  │
│     定义强制行为：分析块、文档门禁、自检表             │
│     ↓                                               │
│  Hooks (守护层)                                      │
│     强制执行：spec-first 不可绕过                     │
└─────────────────────────────────────────────────────┘
```

Skills 和 Hooks 是互补关系，不是替代关系：
- **Skills** 调用时，Hooks 依然检查 spec-first
- **Hooks** 不会因为使用了 Skill 而放宽
