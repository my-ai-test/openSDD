# FD-PORTABLE：可移植 SDD 执行框架

## 范围

将 SDD 工作流与宿主协议分离。规则、运行时、适配器和最终变更验证共享同一套项目配置。文件规则是开发流程守卫，不是防恶意进程的文件系统安全边界。

## 验收标准

- AC-001：读取、分析和规格编辑不要求提前解锁；受管业务代码写入必须绑定本会话当前任务，并具有有效规格证据。
- AC-002：证据包含非空规格、明确存在的 AC、受管代码范围和测试设计；允许关联已有正确 AC，禁止通过无关文件或空白规格解锁。
- AC-003：规格摘要变化、代码范围不符、任务结束、会话未绑定时阻止代码写入。恢复会话重新检查摘要；新会话不继承其他会话绑定。
- AC-004：支持绝对/相对路径、Windows 分隔符、中文空格、创建/编辑/删除/移动、多文件补丁；越界或无法解析的写工具不得静默通过；同次规格和代码修改不视为规格先行。
- AC-005：Claude、Codex、Kimi、OpenCode V1/V2 事件适配为同一操作模型；成功后事件不自动把规格写入升级为就绪；失败事件不产生就绪状态。
- AC-006：安装合并自身 Hook 配置并保留用户配置/已有 AGENTS.md 与 CLAUDE.md；重复安装幂等；冲突提前报告；卸载只删除仍与安装记录一致的受管内容。
- AC-007：最终变更验证支持工作区及 Git base/head 范围，逐个业务文件检查任务、AC、测试关联和验证证据。规格可早于当前提交存在。
- AC-008：历史采用率在无代码样本时报告 N/A，例外单列；运行时与独立验证器使用相同代码/测试/规格分类。
- AC-009：doctor 区分文件安装、协议自检和真实宿主事件回执；缺少宿主执行或信任不得报告激活成功。
- AC-010：自带无网络依赖的自动测试，覆盖正例、拒绝路径、并发会话、状态损坏、安装冲突和配置保留。CI 在 Windows/Linux 使用同一验收命令。

## 完成边界

任意 shell/MCP/外部编辑的完整静态写路径识别不作保证；可审计模式明确记录未覆盖调用，严格模式拒绝未识别工具。最终验证不能从 diff 证明编辑时序，也不能证明 AC 的业务语义充分性。
