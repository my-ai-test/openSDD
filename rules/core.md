# SDD 核心执行规则

## 项目上下文

先读取消费项目 `.sdd/config.json`。目录相对项目根解析；`frameworkDir` 指向框架，`specDirs`、`codeDirs`、`testPatterns`、`testCommand` 由项目定义。按 `profiles` 加载框架中的同名 profile，未选择的架构、ORM、企业约定不适用。

## 执行流程

1. 先允许只读调查：读取项目指令、相关规格、模板、BACKLOG、接口和测试配置。
2. 首次业务代码写入前说明分类、FD/AC、欠账关联、文档影响和验证计划。未读取文件时不得声称已检查。
3. 创建规格前读取模板。变化的业务行为先改规格；已有 AC 正确的 Bug 修复引用原 AC 并解释为何无需改规格。
4. 在实现前将 AC 推导出的测试场景固化到测试设计文档。可查看接口签名，断言以业务结果为依据。
5. 按 `docs/runtime.md` 创建任务清单、准备规格证据并绑定当前会话。代码范围限定到任务涉及文件/模块；跨工具继续时重新绑定和验证摘要。
6. 实现代码和测试，按项目配置运行验证。Mock 使用完整接口工厂，不以实现现状推导期望结果。
7. 运行独立验证器，报告实际命令、结果、文档同步和未完成项。失败先修复再复验，未运行不能标记通过。

## 文档同步

| 变更 | 检查/更新 |
|---|---|
| 功能、AC、业务规则 | Feature Spec |
| Schema、字段 | DATA_SPEC |
| API 入参、出参、端点 | API_SPEC 的“已实现端点详细契约” |
| 界面、交互 | UI_SPEC |
| 权限、认证、审计 | SECURITY_SPEC |

不涉及的项目说明 N/A。BC 使用 `templates/spec/L1-BC_SPEC.md`；DDD_SPEC 是架构约束，不代替 BC 模板。关联 BACKLOG 按用户已授权范围处理。

## 例外与覆盖边界

非行为变更可使用具备具体理由、有限代码范围的 `exception` 任务，例外独立报告，不计规格覆盖。不得用无关规格、空文件、伪造测试结果解锁。Shell/MCP 审计模式不承诺拦住全部写入，最终变更验证和 CI 必须执行；严格模式拒绝未支持的工具路径，也可能阻止 shell 测试命令。

## Skills 编排

按技能名称加载 SKILL.md，并顺序执行输入/产物流程。调用入口见 `docs/hosts.md`。宿主不支持嵌套时由当前 Agent 顺序执行子流程，不递归创建子 Agent，不把 slash 命令当 shell 执行。
